# 01. 비전공자용 전체 설명

## ScopeLease가 해결하려는 문제

AI 코딩 에이전트는 코드를 고치거나 분석할 때 세 가지 문제가 자주 생긴다.

첫째, 어디를 봐야 할지 몰라 저장소를 넓게 뒤진다. 이러면 모델 입력이나 탐색량이 커지고 시간이 늘 수 있다.

둘째, 위험한 작업과 별로 위험하지 않은 작업을 사용자에게 비슷하게 묻는다. 사용자는 매번 판단해야 하므로 피로해진다.

셋째, 한 번 허용한 작업이 어디까지 허용된 것인지 불분명하다. 예를 들어 `npm test` 실행은 허용했지만 `npm test && rm -rf .`까지 허용한 것은 아니다.

ScopeLease는 이 세 문제를 한 번에 다룬다.

## ScopeLease의 기본 접근

ScopeLease는 AI에게 저장소 전체를 더 많이 보여주는 시스템이 아니다. 반대로, 지금 작업에 필요한 부분을 먼저 좁히는 시스템이다.

ScopeLease는 저장소를 분석해 파일, 함수, import, 테스트, 문서, route, 정책 hit를 연결한 지도를 만든다. 이 지도를 여기서는 저장소 지식그래프라고 부른다.

그 다음 현재 저장소 상태와 기준점을 비교한다. 기준점은 "이전에는 여기까지 안전하다고 본 상태"에 가깝다. 기준점과 현재 상태가 다르면, 어떤 파일이 바뀌었는지, 그 변경이 어떤 테스트나 문서와 이어지는지 계산한다.

그 결과 에이전트에게 다음을 준다.

- `readPlan`: 먼저 읽어야 할 파일과 이유
- `avoidPlan`: 지금 작업에서는 피해야 할 범위
- `traceLedger`: 왜 이 범위를 골랐는지에 대한 근거 기록
- `decisionGate`: 자동 진행, 사용자 승인, 거부 중 어떤 판단인지

## 핵심은 approval lease

ScopeLease에서 가장 강한 특허 포인트는 approval lease다.

approval lease는 단순히 "사용자가 승인했다"를 저장하는 기록이 아니다. 다음 조건이 묶여 있는 승인권이다.

- 어떤 사용자 요청에 대한 승인인지
- 어떤 저장소 기준점에서 승인했는지
- 어떤 위험도까지 허용되는지
- 어떤 파일 범위까지 허용되는지
- 어떤 명령 범위까지 허용되는지
- 승인 당시 어떤 파일이 변경되어 있었는지
- 어떤 일이 생기면 다시 멈춰야 하는지
- lease 내용이 바뀌지 않았는지 확인하는 HMAC 서명

따라서 ScopeLease는 "한 번 승인했으니 계속 진행"이 아니다. "이 요청, 이 기준점, 이 파일, 이 명령, 이 위험도 안에서만 계속 진행"이다.

## 비전공자용 비유

일반 에이전트는 큰 회사 건물에서 필요한 문서를 찾는 직원과 비슷하다. 어디를 봐야 할지 모르면 건물 전체를 돌아다닌다. 그리고 방을 열 때마다 사용자에게 "들어가도 되나요?"라고 물을 수 있다.

ScopeLease는 이 직원에게 다음을 준다.

- 오늘 업무와 관련된 방 목록
- 들어가면 안 되는 방 목록
- 한 번 승인받은 범위가 적힌 출입증
- 출입증이 조작됐거나 범위를 벗어나면 멈추는 검사대

이 비유에서 출입증이 approval lease이고, 검사대가 lease validation이다.

## 특허적으로 중요한 차이

넓게 보면 기존에도 코드 검색, MCP, 워크스페이스 컨텍스트, AI 코드리뷰, permission prompt는 존재한다. 그래서 "AI에게 코드 지식그래프를 준다"만으로는 약하다.

ScopeLease의 차이는 조합에 있다.

```text
저장소 지식그래프
+ 기준점 비교
+ compact context
+ action-specific guard
+ HMAC-signed approval lease
+ 후속 작업마다 scope/signature 재검증
+ paired metering
```

이 조합을 좁고 구체적으로 써야 한다.

## 한 줄 결론

ScopeLease는 AI 코딩 에이전트에게 더 많은 권한을 주는 시스템이 아니라, 필요한 컨텍스트와 허용 범위를 계산하고, 승인된 범위만 반복 사용할 수 있게 검증하는 시스템이다.
